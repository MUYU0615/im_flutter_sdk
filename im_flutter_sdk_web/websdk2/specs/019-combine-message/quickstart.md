# 019 快速验证指南（Phase 1）

## 目标

验证合并消息在发送、接收、按需解码、嵌套限制与跨平台语义上的一致性。

## 前置准备

1. 安装依赖：

```bash
npm install
```

2. 准备可用测试账号与会话（单聊/群聊至少各一组）。

3. 准备跨平台运行环境：

- Web 浏览器
- 微信小程序开发者工具
- uni-app（小程序 / App / H5）
- Electron Renderer
- React Native

## 验证步骤

### 步骤 1：基础回归

```bash
npm run test:run
npm run lint
```

期望：现有非合并消息链路全部通过，确保引入 `combine` 前后无回归。

### 步骤 2：发送合并消息

- 构造包含 `txt/img/file/custom` 的 `messageList`。
- 发送合并消息并确认最终消息 `type = combine`。
- 验证回调中的 `url/secret/fileLength/combineLevel` 字段完整。

期望：编码 -> 上传 -> 发送闭环成功。

### 步骤 3：嵌套与上限校验

- 使用含已有合并消息的 `messageList` 再次发送，验证 `combineLevel` 自动计算。
- 构造 `combineLevel > 10` 场景，验证发送被拒绝。
- 构造条数 `>300` 场景，验证发送被拒绝。

期望：层级与条数边界全部命中预期错误。

### 步骤 4：接收回调与按需解码

- 接收一条下行 `combine` 消息，验证默认只回调元信息。
- 调用按需详情 API（参考旧工程 `downloadAndParseCombineMessage` 语义）获取子消息列表。
- 校验返回顺序与发送输入顺序一致。

期望：接收回调与按需解码分层行为正确。

### 步骤 5：按需解码失败策略

- 模拟详情下载失败，验证返回下载阶段错误。
- 模拟单条子消息解析失败，验证整体失败且不返回部分结果。
- 模拟详情条数超限（>300），验证拦截失败。

期望：全部失败场景返回可识别错误，且符合“整体失败”契约。

### 步骤 6：跨平台一致性

- 在各目标平台重复步骤 2~5。
- 对比发送回调字段、错误码、按需解码结果顺序。

期望：跨平台行为语义一致。

## 验收清单（对应 spec）

- 发送闭环：通过率 100%
- `messageList` 顺序一致性：通过率 100%
- 详情解码“整体失败”契约：通过率 100%
- `combineLevel` 与条数上限拦截：通过率 100%
- 非合并消息回归：通过率 100%

## 常见失败定位

- 发送前即失败：优先检查 `messageList` 类型白名单、条数、层级限制。
- 上传失败：检查平台上传能力、鉴权透传、资源返回字段。
- 详情解码失败：检查下载能力、二进制完整性、子消息协议可解析性。
