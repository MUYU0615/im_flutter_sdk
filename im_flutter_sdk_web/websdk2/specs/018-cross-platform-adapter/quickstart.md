# 018 快速验证指南（Phase 1）

## 目标
快速验证跨平台适配层的最小可用闭环与一致性语义。

## 前置准备

1. 安装依赖：

```bash
npm install
```

2. 准备平台运行环境：
- Web（浏览器）
- 微信小程序开发者工具
- uni-app（小程序 / App / H5）
- React Native 运行环境
- Electron Renderer 运行环境

3. 准备可用鉴权参数（`appKey/userId/token`）与测试频道。

## 验证步骤

### 步骤 1：基础回归（Web）

```bash
npm run test:run -- tests/unit
npm run lint
```

期望：现有 Web 链路通过，未因适配层改造出现回归。

### 步骤 2：平台识别与初始化

- 在每个目标平台执行 SDK 初始化。
- 验证初始化返回的平台标识与能力画像符合预期。
- 对“关键能力缺失”注入场景，验证初始化 fail-fast 且返回统一错误结构。

### 步骤 3：文本消息闭环

- 每个平台执行：初始化 -> 登录 -> 建连 -> 发送文本 -> 接收回调。
- 验证：对外 API 不变、消息状态流转一致、连接事件语义一致。

### 步骤 4：附件消息闭环

- 分别使用 Web File / MiniApp path / RN uri 触发上传并发送附件。
- 验证：进度事件字段统一（`loaded/total/percent`），失败与取消语义统一。

### 步骤 5：连接恢复语义

- 模拟离线恢复、前后台切换、异常断连。
- 验证：重连触发条件与状态事件语义跨平台一致。

### 步骤 6：编解码一致性

- 对同一组消息样本执行跨平台 encode/decode 对比。
- 验证：关键字段语义一致；同版本仅启用单一静态 protobuf 方案。

## 验收清单（对应 spec）

- 文本消息闭环通过率：100%
- 附件上传语义一致性通过率：100%
- 连接恢复语义一致性通过率：100%
- 编解码关键字段一致性：100%
- `uni-app H5` 独立验收记录完整且通过率：100%

## 常见失败定位

- 初始化即失败：优先检查平台能力缺失与适配器注入配置。
- 上传失败：检查平台文件源对象规范化结果与鉴权头透传。
- 编解码失败：检查静态 protobuf 产物版本与消息样本一致性。
