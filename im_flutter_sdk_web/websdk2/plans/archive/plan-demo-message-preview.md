# Demo 消息列表展示修复计划

## 背景与问题
- 当前消息列表主要依赖 onMessage（收消息），自己发出的消息若无回显不会展示。
- 列表展示仅优先读取 body.message，附件类型/空文本会显示为 `{"message":""}`，难以判断类型。
- 需求：支持展示图片/视频/语音/文件等附件类型，并提升消息可读性。

## 目标
- 消息列表同时展示收发消息（含发送中/成功/失败状态）。
- 按消息类型渲染内容，附件类型可预览（图片/音频/视频）或显示可下载链接。
- 明确显示消息类型、发送者与时间，避免空内容误导。

## 实施步骤
1. App 层新增消息“去重并更新”逻辑，接入 onMessageStatus：
   - 通过 msgLocalId / msgServerId upsert，避免重复。
   - onMessageStatus 触发时更新消息状态并展示。
2. MessagePanel 增强展示逻辑：
   - 按 message.type 渲染文本、图片、语音、视频、文件、位置、命令、自定义等内容。
   - 使用 body.url / thumbnailUrl / thumb / data 生成预览或链接。
   - 为空或不完整内容提供占位提示。
3. 样式补充（如有必要）：
   - 为附件预览添加基础样式，避免撑破布局。
4. 版本与日志：
   - 版本号按 patch 递增。
   - 更新 CHANGELOG.md。
5. 验证与提交：
   - 运行 `npm run lint`。
   - 运行 `npm test -- --run`（若 real-env 测试失败，记录原因）。
   - 仅提交本次修改文件。

## 风险与规避
- 预览 URL 为本地 ObjectURL 可能需要释放：使用 URL 直出且无需手动管理时保持简单，必要时再优化。
- 不同消息体字段可能缺失：渲染时使用类型守卫与兜底提示。

## 预期产出
- Demo 消息列表可清晰显示发送/接收消息及附件预览。
- 空内容不再显示为 `{"message":""}` 的疑惑状态。
